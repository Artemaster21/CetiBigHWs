## Запуск

### 1. Версия на `requests` (8 баллов)

```bash
python solve8.py
```

Программа:
1. Устанавливает cookie `user=91e7c7839a479f5895216100cb651a6a`.
2. Проходит цепочку заданий (GET / POST / multipart upload).
3. Печатает секретный токен в консоль.

Результат сохраняется в `solve_log.txt`.

### 2. Версия на `curl` (10 баллов)

```bash
chmod +x solve_curl.sh
./solve_curl.sh
```

Bash-скрипт использует `curl` для всех типов запросов:
- GET с query-параметрами и cookie,
- POST с заголовками, cookie и телом формы,
- multipart-загрузка файлов через `-F`.

### 3. Версия на raw sockets (12 баллов)

```bash
python solve_raw.py
```

Программа **не использует `requests`**: она сама формирует HTTP-запросы
(стартовая строка, заголовки, тело) и отправляет их через `socket`.
Ответ читается и парсится вручную.

## Что было сделано

### Типы шагов на сервере

1. **GET с query-параметрами** — «При переходе выставьте параметры запроса».
2. **GET с cookie** — «В запросе должны быть выставлены cookie».
3. **GET с заголовками и/или cookie** — «Запрос должен иметь следующие заголовки».
4. **POST с заголовками / cookie / данными формы** — комбинации в разных порядках.
5. **multipart/form-data upload** — «Загрузите файлы по адресу ...».

### Ключевые моменты реализации

- **Cookie всегда содержит `user=<токен>`**, остальные cookie приходят из задания.
- **Порядок фраз в HTML не фиксирован** (заголовки могут идти до или после cookie),
  поэтому таблицы сопоставляются фразам **по позиции в HTML**.
- **Файлы загружаются как multipart/form-data** с корректными boundary
  и `Content-Type`.
- **Кириллица в значениях cookie и headers** кодируется в UTF-8
  (важно: HTTP-заголовки по стандарту latin-1, поэтому все кириллические
  значения отправляются через тело запроса или cookie).
